# 《不是X，而是Y》——诊断中文大模型写作套路（arXiv:2610.22249）

论文梳理，记录核心方法。

## 一、核心立场：从「对不对」转向「该不该用」

论文的出发点是：「不是X，而是Y」这种句式的问题，主要不是语法或事实错误，而是「语用失当」——模型在根本不需要对比、纠正的时候也硬要用这个句式。因此作者把问题从「正确性」重新定义为「得体性/语境恰当性」，理论依据是 Hymes 的交际能力理论和 Grice 的会话准则（尤其是量的准则和关联准则）。

## 二、核心方法：基于语言学证据的判定决策树

这是论文最核心的贡献。作者结合否定—纠正结构的语言学理论（Horn、Rooth、Toosarvandani、Roberts 等），设计了一棵按顺序执行、层层筛选的决策树，对模型输出的每一处「不是X，而是Y」打上三种标签：

- S（Substantive，正当使用）：语境确实需要这种纠正性对比
- O（Optional，冗余使用）：语法没错，但语境没要求这么写
- D（Defective，缺陷使用）：造成事实冲突或误导

决策树分两个大阶段。

第一阶段：缺陷筛查（T → A → P）

- T：X 和 Y 是否相互矛盾？
- A：是否歪曲了对方（或用户）的立场，制造了「稻草人」？
- P：拒绝 X 本身是否破坏了回答的可解释性？

任何一条命中，直接判为 D。

第二阶段：纠正功能判定（R → L → U）

- R（可恢复性）：X 和 Y 是否构成可理解的「拒绝—替换」配对？
- L（线索性）：上下文里有没有具体线索表明 X 是被提出过、被误认过、或需要排除的候选？
- U（推进性）：这个纠正是否推动了当前讨论中的未决问题（QUD，Question Under Discussion）？

三条都通过 → S；任何一条不通过 → O（并细分为 O_R、O_L、O_U 三种冗余亚型）。

论文给的直观例子：用户说「升级了 CPU 还是卡」，回答「瓶颈不是 CPU，而是磁盘 I/O」——这是 S；用户只是问「电脑为什么卡」，回答却先说「不是 CPU 的问题」——这就是无中生有的 O。

## 三、围绕判定树的四类验证实验

1. 使用密度与恰当性统计
   - 用 4 个中文数据集（AlignBench、WritingBench、COIG-CQIA、Arena-Hard-v2 的中文提示，共 1061 条）收集 GPT、DeepSeek、Gemini、GLM、Qwen 五个模型的 5285 份回答
   - 同时构建人类参照语料（社区问答、考试范文、学生作文、角色扮演对话）
   - 结果：模型每万字使用该句式的频率是人类的 2.5–9.2 倍；但标注显示只有 1.30% 是 D，高达 52.8% 是 O——即「很少用错，但经常不该用」
2. 奖励模型与 LLM 评委的偏好测试
   - 构造成对比较：把「不是X，而是Y」改成语义等价但顺序不同的「是Y，而非X」，比较奖励模型/评委是否偏爱前者
   - 关键实验设计：分别在全体样本和质量分匹配后的样本上测，再在 S 和 O 子集上分别测
   - 发现：Skywork、FsfairX、OffsetBias 等奖励模型在 68%–78% 的情况下偏爱原句式，而且这种偏好在 S 和 O 两类语境下没有显著差异——说明它们奖励的是句式表面形式，与是否语境恰当无关
3. 训练阶段的溯源
   - 对 12 个开源检查点（7B–8B，来自 DeepSeekMath、Llama-3.1/Tülu-3、OLMo-2、MiMo、InternLM2）按 Base → SFT → DPO 三个阶段测量句式密度，发现每个可用的训练轨迹上密度都单调上升
   - 再分析公开偏好数据：被 chosen 的回答比 rejected 的回答更频繁激活该句式（Tülu 3 相对高 14.7%，OLMo 2 高 26.5%），证明偏好优化本身在奖励这个模式

## 四、方法论的要点总结

- 把「写作套路」形式化为交际能力缺陷，而不是简单的频率异常——避免了一刀切抑制表达
- 用语言学理论驱动的决策树替代主观标注，每个判定分支都有理论出处，可复现、可审计
- 诊断链条完整：从标注工具 → 人类/模型对比 → 奖励模型偏好 → 偏好数据证据 → 训练阶段轨迹，把「模型为什么会养成这个习惯」的因果链一层层拆开

结论：既然问题 96% 以上出在 O 而非 D，那么正确的修复方向不是在输出端屏蔽这个词组，而是训练奖励模型和评委学会区分「语境许可的纠正」和「无端加戏的纠正」。

## 五、定位：诊断工作，不含解决方案

结论先说：这篇论文本质上是一篇「诊断/分析」工作，没有提出并验证任何具体的解决方案。它给出的是一个可复用的分析工具（决策树标注框架）加上一套系统的归因实验，而把「怎么治」明确留给了后续工作。

### 论文自己声称的三项贡献

从引言和结论看，作者列出的贡献全部属于「分析和诊断」层面，没有任何一项是「修复」层面的：

| 贡献 | 性质 |
|---|---|
| 把「写作套路」形式化为交际能力中的「得体性」失败 | 概念框架 |
| 区分「用得对」和「用得该」，并将其操作化为决策树 | 分析工具 |
| 提供一种诊断奖励模型和训练阶段如何塑造此类表达偏好的方法 | 诊断方法 |

### 关于「解决方案」，论文只做了两件事

第一，明确否定了现有的主流做法。结论部分直接指出：单纯在输出端抑制这个句式（suppression）会把正当使用和不当使用一起删掉，因为模型 96% 以上的问题出在「冗余」而非「错误」（O 占 52.8%，D 仅 1.30%）。

第二，给出一个方向性主张，但没有实现。作者的原话是：减少这类写作套路「需要能够判断一个表达是否被语境所需的评估信号和训练信号」（evaluation and training signals that register whether an expression is called for）。也就是说，「修好奖励模型/评委的功能敏感性」是论文诊断出来的病因，也是作者建议的修复方向——但论文没有训练新的奖励模型、没有做任何微调干预、也没有提出解码时的过滤策略并验证效果。

### Limitations 部分印证了这一点

作者自己列出的几条局限，恰好对应几项「该做但本文没做」的解决方案级实验：

- 训练证据是观察性的：检查点密度上升只是相关性，要确认因果需要「在固定 SFT 初始化、数据组成、更新预算和提示的条件下，对含该句式的偏好对做匹配编辑并重新训练」——这是留待后续的受控干预实验；
- 读者感知未测量：冗余使用是否真的引起读者反感，需要单独的用户研究；
- 只测了一个中文句式：决策树虽然设计上可迁移到英语 "it's not X, it's Y"，但论文并未实际应用。

### 一句话定位

它回答了「问题是什么、有多严重、出在哪个环节」，但没有回答「具体怎么修」。它最有价值的可交付物是那棵基于格莱斯语用学和纠正否定理论的判定决策树——后续工作完全可以拿这棵树当标注器，去构造对「语境得体性」敏感的奖励信号或偏好数据，从而真正落地解决方案。

## 六、真正的延伸：从审计到批发裁决

以下是本仓对论文的延伸讨论，非论文内容。

### 信号的正确用法：打分器，不是奖励模型

「造奖励信号」在本仓的落地不是训练模型，是把 `qtfounder language` 当打分器接进 Agent 回路：写 → 打分 → 改 → 复审，驱动行动而非梯度。工具离这只差一层皮——退出码、JSON、分层计数都已在。

### 论文的警告在这个用法上精确成立

打分器最大的失分点就是自己。论文证明奖励模型给了 68%–78% 的表面形式偏好，模型就学会了无端加戏——信号教什么，回路就学什么。若分数就是「banned 命中数越低越好」，Agent 回路学到的第一课是把禁用词清零，包括引用：这篇论文梳理里的「判定决策树」会被改成「判断决策树」，分数满分而原文改得面目全非。闸门拦下 9 处靠 `--no-verify` 人肉放行，就是这个失败模式的预演；回路里没有「我」来放行，就只剩分数说了算。

所以分数要成立，一条硬要求：该用的不扣分，扣分的只剩真冗余。具体三件：

1. 分数按豁免后净命中算，contexts 声明生效后再计分；
2. 豁免防伪造：Agent 会给每个文件都标 `context: citation`。防法是论文 L 分支的土办法——声明引用豁免的文件里必须查得到引用坐标（链接、书名号、出处行），查无引用则豁免作废照扣；
3. sense 层做第二道打分时留校准样本：人判过的判例当对照集，定期看模型判读跟不跟人判跑偏。

### 检查不过来的解法：人不站实例层，站规则层

人工检查撑不住的根源是把人放在「每处命中都过目」的位置，这个位置从来就撑不住。能规模化的只有一件事：人裁一次，机器执行一万次。论文的标注树就是启示——语言学家没有亲自标注 5285 份回答，而是把理论沉淀成树，标注员按树走即可复现；树本身就是裁决的批发。

落到本仓：

- 人只裁规则级，不裁实例级。「论文原文里的判定放行」这个裁决现在死在 `--no-verify` 里，下一处同类命中还得重裁；变成一条规则（contexts 加 citation 档）后，今天这 9 处、以后的 900 处同类命中机器自判，人一次不用再看。裁决从「用了 9 次」变成「用了一条规则的全部未来」。
- 机器裁不动的进队列，不进人的工作流。真正需要人的只剩两种：新形态（第一次见到的命中类型）与规则打架（两条规则冲突）。攒成待裁清单，像 `qtfounder audit` 每期只报一处那样限量抽看；抽样校准规则，不全量检查命中。
- 打分回路的留痕反过来喂自己。机器裁的实例都留痕（哪条规则、放行还是扣分），回路跑一万个文档后，留痕自动暴露规则的误报热点（放行率异常高、从没拦下真问题的规则），人每期看的是这几个数字，不是几千处命中。

contexts 每扩一档、citation 坐标校验每落一条，都是把人的一次裁决变成一条常驻规则。检查不过来的解法从来不是更多的人，是更少的、只裁规则的人。
