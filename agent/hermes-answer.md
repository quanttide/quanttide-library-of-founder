# Hermes 输出行为的控制机制

把「一个 agent 的回答是怎么被管住的」拆开看，大致分五层，另有两处不在它自己手里。

## 一、人格层

一份单一人格提示，规定长度与语气基准：长度与问题的重量匹配；完成的工作给短报告，只写改了什么、验证了什么、还差什么，不复述过程；不用填充语，不复述请求，不叙述用户已能看见的工具调用；不确定就直说；默认不给深度，深度要挣。

这一层最容易失守。典型失败是把「验证过」当成必须展示的正文，于是审计细节占据前半段，结论被压到末尾。

## 二、每轮重建的系统提示

硬约束，随每次请求重新拼装，agent 改不了自己：

- 必须真调工具，不能只描述意图；
- 必须有真实产出，不能交计划代替结果；
- 相互独立的调用要并行批量发起；
- 对外部系统的写入要读回验证；
- 平台格式偏好（例如消息长度、Markdown 可用性、媒体发送方式）。

## 三、记忆

两份常驻记忆——一份记用户的身份与偏好，一份记 agent 自己的经验与约定——每轮全文注入。它们决定风格的上限：用什么语言、答多少、什么算越权、报告按什么骨架写。

两处约束值得记下：记忆有字符预算，写满必须先淘汰旧条目，所以记忆是选择性的；偏好与系统提示冲突时，agent 往往偏向系统提示，于是出现「用户嫌啰嗦、agent 仍堆证明」的反复。

## 四、技能库

按需加载的程序性记忆。每条技能规定一类任务的做法，例如技术文档写作的铁律（读者视角、叙事按读者的问题顺序、禁自造口语化概念）、报告的骨架（意图、结果、边界、下一步）。

技能的代价是触发条件敏感：该加载时没加载，agent 就退回一般经验；不该加载时乱加载，会拿别处的规矩套当前的活。

## 五、工具与审批策略

这一层直接约束动作，也间接塑造输出：

- 危险命令默认要确认，但部分高危命令可以预放行——放行范围是可配置项；
- 覆盖已存在的文件前必须先读过全文，否则拒绝写入；
- 仓库级的说明文件受写入保护，需所有者明确同意；
- 同一失败重复出现会触发循环警告，逼 agent 换策略而不是重试；
- 单轮有工具调用上限，超限即止。

## 两处不在自己手里

**会话压缩。** 早期上下文会被压成摘要，agent 记住的是摘要而不是原文；要精确细节只能回查历史会话。压缩本身会改变判断依据。

**模型侧解码。** 采样参数、上下文窗口、训练偏好都由所接入的模型决定，通常不在 agent 的配置里。

## 一处结构性冲突

系统提示要求「报验证结果、证明真做了」，用户偏好常常是「只答被问的那块、别堆细节」。两条同时生效时，冲突不能靠自觉解决，只能靠显式口径：把「证据」放进固定位置（例如附录），正文只留结论与待决项。

若不显式规定，默认行为总是偏向证明——因为证明是可验证的，而「读者需要多少」无法自证。
